**Problem Statement**
You are given an initially empty array of integers. You have to process `q` queries of the following two types:

- `1 x` — append the number `x` to the end of the array;
- `2 x y` — replace **all** occurrences of `x` in the current array with `y`.

After performing all queries, output the final contents of the array.

**Input Format**
- The first line contains one integer `q` (`1 ≤ q ≤ 5 · 10^5`) — the number of queries.
- The next `q` lines each describe one query in one of the following forms:
  - `1 x` where `1 ≤ x ≤ 5 · 10^5`
  - `2 x y` where `1 ≤ x, y ≤ 5 · 10^5`

It is guaranteed that there is at least one query of type `1`.

**Output Format**
Print the resulting array after all queries, as `k` integers in one line, where `k` is the number of queries of type `1`.

**Examples**
Sample Input 1
```
7
1 3
1 1
2 1 2
1 2
1 1
1 2
2 1 3
```

Sample Output 1
```
3 2 2 3 2
```

Sample Input 2
```
4
1 1
1 2
1 1
2 2 2
```

Sample Output 2
```
1 2 1
```

Sample Input 3
```
8
2 1 4
1 1
1 4
1 2
2 2 4
2 4 3
1 2
2 2 7
```

Sample Output 3
```
1 3 3 7
```

**Editorial**
A direct simulation is too slow because query `2 x y` may need to update many elements.

Process the queries **from the end to the beginning**. Maintain an array `p`, where `p[v]` means: *if a value equals `v` at this moment (looking from the end), what value will it become after applying all already processed replace-queries*.

Initialization: `p[v] = v` for all `v`.

Now consider queries in reverse order:

- If the query is `1 x` (append), then in the final array this appended value will become `p[x]`. So we add `p[x]` to an answer list.
- If the query is `2 x y` (replace all `x` with `y`), then any `x` that appears earlier will ultimately become whatever `y` becomes, so we set:
  - `p[x] = p[y]`

At the end, we reverse the answer list (because we collected appended elements backwards) and print it.

Each query is handled in `O(1)`, so the total complexity is `O(q + M)` with `M = 5 · 10^5`, and memory usage is `O(q + M)`.

(Alternative idea: process in forward order and store positions for each value, merging position lists using “small-to-large”, giving `O(q log q)`. The reverse-processing solution above is simpler and faster.)

**Code**
```python
import sys


def main() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    q = data[0]
    idx = 1

    typ = [0] * q
    xval = [0] * q
    yval = [0] * q

    for i in range(q):
        t = data[idx]
        x = data[idx + 1]
        idx += 2
        typ[i] = t
        xval[i] = x
        if t == 2:
            y = data[idx]
            idx += 1
            yval[i] = y

    X_MAX = 500000 + 5
    p = list(range(X_MAX))

    ans = []
    for i in range(q - 1, -1, -1):
        if typ[i] == 1:
            ans.append(p[xval[i]])
        else:
            p[xval[i]] = p[yval[i]]

    ans.reverse()
    sys.stdout.write(" ".join(map(str, ans)) + "\n")


if __name__ == "__main__":
    main()
```
